# 프로젝트 페이지 만들기

요청: $ARGUMENTS

이 페이지는 이력서를 보고 들어온 채용 담당자·면접관이 읽는다. "무엇을 했는가"보다 "어떤 문제를 어떻게 풀었고 결과가 어땠는가"가 드러나야 한다.

1. 아래 정보 중 요청이나 대화에 없는 것을 사용자에게 한 번에 물어본다. 추측해서 채우지 않는다.
   - 경력(work)인지 사이드(side)인지, work라면 회사명
   - 기간, 본인 역할과 팀 규모
   - 사용 기술
   - 해결하려던 문제, 핵심 기여, 결과(가능하면 수치)
   - 공개 가능한 저장소·데모 링크
2. work 프로젝트면 `src/data/profile.ts`의 `experience`에 같은 `company`가 있는지 확인한다. 없으면 경력 항목도 추가할지 사용자에게 묻는다 (company 문자열이 정확히 같아야 About 페이지에서 연결된다).
3. 영문 kebab-case slug로 `src/content/projects/<slug>.md`(이미지가 있으면 `<slug>/index.md`)를 만든다. frontmatter는 CLAUDE.md의 "프로젝트" 규칙을 따른다.
4. 본문은 `## 배경` → `## 문제` → `## 해결 과정` → `## 결과` → `## 배운 점` 순서로 쓴다. 받은 정보로 채우고, 없는 부분은 `<!-- TODO: ... -->`로 남긴다. 회사 내부 정보(내부 시스템명, 매출 등 비공개 수치)가 들어가 있으면 공개해도 되는지 확인한다.
5. 대표 프로젝트로 홈에 띄울지(`featured: true`) 묻는다.
6. `npx astro check`와 `npm run build`가 통과하는지 확인하고, 파일 경로와 URL(`/projects/<slug>/`)을 알려준다.

커밋·푸시는 사용자가 요청할 때만 한다.
