## 배경

The Traveling Soul은 현대자동차·기아의 오픈이노베이션 조직 [제로원(ZER01NE)](https://brunch.co.kr/@zer01ne/41)이 운영하는 2026 이그나이트(Ignite) 프로젝트입니다. 이그나이트는 현대차·기아 임직원과 외부 크리에이터가 함께 관심 있는 기술을 실험하는 트랙이고, 저는 외부 크리에이터로 참여했습니다.

이름에 '영혼'이 들어가 있지만 오컬트 프로젝트는 아닙니다. 여기서 '영혼'은 AI의 기억과 맥락, 성격을 하나로 묶은 것입니다. 이 영혼이 차량, 모바일, 로봇 개 스팟(Spot), 스마트홈을 옮겨 다니며 사용자를 따라갑니다. 기기를 바꿀 때마다 "아까 무슨 얘기 하셨죠?"라고 되묻지 않는 AI라고 생각하면 쉽습니다.

이렇게 AI가 화면을 벗어나 로봇이나 기기의 몸을 빌려 실제 공간에서 보고, 움직이고, 반응하는 것을 **피지컬 AI(Physical AI)**라고 부릅니다. 이 프로젝트가 만들려는 것은 그중에서도 늘 곁에 있는 '피지컬 AI 동반자'입니다.

목표는 화면 안에 갇혀 있던 AI를 실제 공간으로 꺼내는 것, 그것도 "오, 신기하다"에서 끝나지 않고 일상에서 진짜 쓸모 있는 경험을 찾는 것입니다.

전체 팀은 기획, 디자인, 로봇, 비전 제어를 포함해 20명 가량입니다. 그중 개발 영역은 크게 넷으로 나뉩니다.

- MoBED 로봇 플랫폼 기반 자율주행
- 사람처럼 자연스러운 로봇 팔 동작, 비언어적 신호(위치, 움직임, 생체 신호)를 활용한 선제적 케어
- 장비 이벤트 데이터(위치, 화면, 음성)를 보여주는 대시보드와 여러 장비를 통합 관리하는 서버
- **사용자 인터랙션 UI와 전시 화면 전체 (본인 담당)**

이 가운데 웹 서비스는 세 명이 함께 개발했습니다. 프런트엔드는 제가, 백엔드는 기아 임직원 한 분이, 미래차 관련 서비스는 다른 외부 크리에이터 한 분이 맡았습니다.

### 참여 계기

20년 동안 회사 일로 코드를 짜다 보니, 누가 시켜서가 아니라 재미있어서 하는 개발을 해 보고 싶어졌습니다. 그렇게 흥미로운 사이드 프로젝트를 찾아 여기저기 기웃거리다가, 현대차그룹 제로원이 The Traveling Soul 프로젝트의 크리에이터를 모집한다는 공고를 발견했습니다.

키워드는 AI와 로봇이었습니다. 영화나 만화에서 AI로 움직이는 로봇을 보며 "저런 건 언제 나오나" 하고 꿈꾸던 사람에게는 그냥 지나치기 어려운 조합입니다. 평소에도 AI에 관심이 많았고, 요즘 피지컬 AI라고 부르는 것, 그러니까 AI와 로봇을 실제로 어떻게 연결하는지 늘 궁금했거든요. 정말로 로봇에 AI를 붙이는 걸까, 붙이면 뭘 할 수 있을까. 궁금증이 꼬리에 꼬리를 물었습니다.

게다가 마침 프런트엔드 엔지니어 포지션이 열려 있었고 지금까지 쌓아 온 개발 경험을 회사 밖 새로운 세상에서 써 볼 기회라는 생각에 지원했습니다.

2026년 4월 킥오프에서는 "Soul Walk"라는 아이디어를 피칭했습니다. 하나의 AI가 차량에서 로봇으로, 로봇에서 집으로 몸을 옮겨 다니며 기억과 감정을 이어받는다는 이야기입니다. 성공 기준도 함께 적었습니다. 체험이 끝난 뒤 "AI가 몇 명이었던 것 같나요?"라고 물었을 때 "한 명"이라는 답이 나오면 성공입니다. 이 아이디어가 그대로 프로젝트의 줄기가 되었습니다.

### 맡은 일

- **아키텍처 설계**: 웹 개발 세 명이 함께 논의해 전체 아키텍처를 정한 뒤 파트를 나눠 작업했습니다. 설계 문서(구성 요소, 메시지 흐름, 상태 관리, 안전·개인정보 원칙)는 제가 직접 써서 팀원들의 검토를 받았습니다
- **전시 화면 개발**: 관람객이 들고 다니는 태블릿, 전시장 대형 디스플레이, TV까지 전시장 화면 다섯 종을 하나의 웹앱으로 만들었습니다
- **인터랙션 연출**: 화면의 스타일과 구성은 디자이너가 맡았고, 글로우·깜박임·소리처럼 화면이 반응하는 방식은 거의 제가 설계하고 구현했습니다

## 문제

AI가 여러 기기를 옮겨 다니며 사용자의 상황을 아무리 잘 이해해도, 사용자가 그걸 모르면 소용이 없습니다. 그렇다고 AI가 매번 "방금 제가 눈치챘는데요"라고 말로 알리면, 그건 동반자가 아니라 잔소리꾼입니다.

그래서 제가 맡은 과제는 AI가 **"알아챘다"는 것을 말없이 드러내는 방법**을 설계하는 일이었습니다. 말 대신 조명이 바뀌고, 로봇이 움직입니다. 눈치 빠른 동료가 말없이 고개를 끄덕여 주는 것처럼요.

막상 만들어 보니 어려움은 화면 밖에서 왔습니다.

- **변화가 조용히 일어납니다.** 화면에 보이는 상태는 대부분 서버가 다시 보내 주는 데이터로 바뀝니다. 카드 색이 살짝 바뀌는 정도로는 관람 거리에서 "방금 끝났다", "방금 도착했다"는 순간이 눈에 남지 않았습니다.
- **화면이 하나가 아닙니다.** 손에 든 태블릿(1280×800, 일부는 4:3 iPad), 2560×1440 대형 디스플레이, TV가 같은 관람객의 같은 순간을 각자 보여 줘야 했습니다. 태블릿 여러 대가 동시에 체험을 진행하기도 합니다.
- **약속이 자주 바뀝니다.** 로봇, 카메라 인식, 서버를 각각 다른 팀원이 동시에 만들고 있어서 주고받는 데이터 형식이 개발 내내 조금씩 바뀌었습니다.
- **센서는 흔들립니다.** 카메라 인식 결과는 1초 단위로 켜졌다 꺼지기도 했습니다. 그대로 화면에 옮기면 화면이 같이 떨립니다.

## 해결 과정

### 화면 다섯 개를 하나의 웹앱으로

처음 설계에서는 태블릿 앱을 React Native로 계획했지만, 실제로는 Next.js 웹앱 하나로 인트로, 태블릿 메인, 하루 마무리 엔딩, 대형 디스플레이, TV 화면을 모두 만들었습니다.

앱으로 출시할 계획이 없었고, 필요한 기능은 대부분 웹 브라우저만으로 충분히 구현할 수 있었습니다. 요구사항을 웹 표준 기술로 모두 채울 수 있다면, React Native를 들여와 런타임과 아키텍처의 오버헤드를 떠안을 기술적 명분이 부족하다고 판단했습니다.

구체적으로는 이런 점들이 웹 쪽으로 기울게 했습니다.

- **화면이 태블릿만이 아닙니다.** 다섯 화면 중 둘은 대형 디스플레이와 TV입니다. React Native로 만들면 태블릿 앱과 별개로 이 화면들을 위한 웹을 또 만들어야 합니다. 웹이면 코드베이스 하나에서 데이터 처리와 상태 관리 코드를 함께 쓰고, 화면마다 마크업만 따로 둘 수 있습니다.
- **필요한 기능이 이미 브라우저에 있습니다.** 음성 입력(마이크 녹음), 효과음(Web Audio), CCTV 실시간 영상(WebRTC), 로티 애니메이션 모두 브라우저 표준 API나 웹 라이브러리로 해결됩니다. 네이티브 모듈이 꼭 필요한 기능이 없었습니다.
- **배포가 곧 업데이트입니다.** 전시 직전까지 하루에도 여러 번 고쳐야 했습니다. 앱이면 기기마다 새 빌드를 설치해야 하지만, 웹은 서버 컨테이너 하나만 바꾸면 모든 화면에 반영됩니다. 계속 켜 두는 대형 디스플레이와 TV는 새 버전을 스스로 알아채고 다시 불러오게 했습니다.
- **앱처럼 쓰는 것도 웹으로 됩니다.** 화면마다 PWA manifest를 따로 두어, iPad 홈 화면에 추가하면 주소창 없이 전체 화면 앱처럼 실행됩니다.
- **서버를 함께 둘 수 있습니다.** Next.js는 화면과 서버(API 라우트)를 한 프로젝트에 담습니다. 브라우저가 직접 붙을 수 없는 MQTT를 이 서버가 대신 받아 넘겨 주는 구조도 별도 서비스 없이 같은 앱 안에서 만들 수 있었습니다.
- **디자인 시안을 그대로 옮기기 쉽습니다.** Figma의 픽셀 값을 CSS rem으로 옮기고 기준 해상도로 통째로 확대·축소하는 방식은 웹 CSS에서 가장 자연스럽습니다. 컴포넌트는 Storybook에서 화면과 따로 확인했습니다.

화면마다 해상도가 달라서, 디자이너의 Figma 기준 해상도로 캔버스를 그리고 실제 화면에 맞게 통째로 확대·축소하는 방식을 택했습니다. 1rem이 늘 기준 해상도의 16px가 되도록 루트 글자 크기를 계산하기 때문에, 어떤 디스플레이에서도 디자인 시안의 비율이 그대로 유지됩니다.

### "알아챘다"를 빛과 소리로

가장 공을 들인 부분입니다. 화면이 직전과 달라진 것만 골라 잠깐 빛나게 하는 공통 규칙을 만들었습니다.

- **색마다 뜻이 하나씩입니다.** 파랑은 시작과 이동, 초록은 완료와 챙김, 코럴은 돌발 상황, 앰버는 일반 알림입니다. 한 색에 두 가지 뜻을 싣지 않습니다.
- **계속 숨 쉬듯 빛나는 것은 화면에 하나뿐입니다.** 둘이 되면 시선이 갈 곳도 둘이 됩니다. 나머지는 한 번 번지고 사라지는 플래시이거나 움직이지 않는 후광입니다.
- **소리는 빛과 같은 순간에 납니다.** 빛은 나는데 소리가 없거나, 소리는 나는데 빛이 없는 경우를 만들지 않으려고 하나의 판정이 둘을 함께 움직이게 했습니다.
- **새로고침은 변화가 아닙니다.** 화면을 다시 열었을 때 기존 카드가 한꺼번에 번쩍이면 연출의 의미가 사라집니다. 그래서 첫 화면과 복원된 상태에서는 연출을 재생하지 않습니다.

### 브라우저와 기기 사이의 다리

로봇, 카메라, 서버는 MQTT라는 메시지 버스로 이야기를 주고받습니다. 그런데 브라우저는 MQTT에 직접 붙을 수 없고, 접속 정보를 화면 코드에 넣을 수도 없습니다. 그래서 Next.js 서버가 중간에서 메시지를 받아 검증한 뒤 브라우저에 실시간 스트림(SSE)으로 넘겨 주고, 태블릿이 보내는 요청은 반대로 서버가 대신 발행하는 구조를 만들었습니다.

개발 도중 "태블릿 한 대에 체험 하나"라는 전제가 틀렸다는 것도 알게 됐습니다. 여러 태블릿과 대형 화면이 서버 하나를 같이 쓰다 보니 한 태블릿의 새 체험이 다른 태블릿의 체험을 덮어쓰는 일이 생겼고, 체험마다 상태를 따로 담도록 구조를 바꿨습니다.

### 전시장에서 깨지지 않게

- **받는 쪽이 너그러워야 합니다.** 데이터 형식이 조금만 달라도 검증에 실패해 메시지 전체가 버려지고 화면이 조용히 멈추는 장애를 여러 번 겪었습니다. 그래서 꼭 필요한 값만 엄격하게 확인하고 나머지는 빠져 있어도 기본값으로 받는 원칙을 세웠습니다.
- **흔들리는 입력은 기다립니다.** 카메라 인식이 깜빡이자 효과음과 알림이 끝없이 반복됐습니다. 값이 2.5초 동안 유지될 때만 반영하도록 바꿨습니다.
- **현장에서 고칠 수 있어야 합니다.** 관람객이 누를 수 있어 설정 버튼을 둘 수 없었습니다. 대신 숨은 제스처로 여는 진단 패널을 두고, 거기서 수신 데이터를 확인하고 지도 위 위치를 현장에서 맞출 수 있게 했습니다.
- **계속 켜 둔 화면은 스스로 새로고침합니다.** 대형 디스플레이와 TV는 아무도 새로고침해 주지 않기 때문에, 새 버전이 배포되면 스스로 알아채고 다시 불러오게 했습니다.

## 결과

2026년 10월 12일부터 16일까지 현대차·기아 양재사옥 로비에서 열린 **2026 제로원 데모데이 '01 EMERGE'**에서 'Physical AI Companion: The Traveling Soul'이라는 이름으로 처음 공개했습니다. 화면 밖으로 나온 영혼이 처음으로 사람들을 만난 자리입니다.

전시된 11개 프로젝트 중 제로원 이그나이트를 대표하는 출품작이었고, 관람객이 차량과 모바일, 로봇을 오가며 자신을 따라오는 AI를 직접 체험하는 형태였습니다.

2026년 4월 피칭부터 10월 전시까지 약 반년이 걸렸습니다. 전시 화면 코드는 6월 말부터 10월 데모데이 직전까지 커밋 약 550개, TypeScript 약 4만 줄 규모로 만들었습니다.

솔직히 관람객이 태블릿 화면을 보며 "같은 AI가 나를 따라온다"고 느꼈는지는 잘 모르겠습니다. 관람객의 눈길을 더 끈 것은 몸을 가진 쪽이었습니다. 스팟이 사람에게 반응하고, 반려로봇이 상황에 맞춰 말을 걸고, 체험 도중 스팟이 마켓까지 가서 물건을 옮겨 오는 모습을 사람들은 훨씬 흥미롭게 지켜봤습니다.

## 배운 점

전시장에서 관람객을 지켜보며 느낀 점들입니다.

**피지컬 AI의 주인공은 몸이었습니다.** 몇 달 동안 가장 공을 들인 건 태블릿 화면의 빛과 소리였습니다. 그런데 관람객이 가장 흥미롭게 지켜본 순간은 스팟이 다가오거나, 반려로봇이 말을 걸거나, 스팟이 물건을 들고 돌아올 때였습니다. 화면을 아무리 다듬어도 실제 공간에서 움직이고 말하는 존재가 주는 반응을 따라가지는 못했습니다. 피지컬 AI라는 말에서 무게가 실린 쪽이 'AI'보다 '피지컬'이라는 걸 현장에서 몸으로 알게 됐습니다.

**화면은 조연이어야 했습니다.** 현장에서 보니 관람객의 시선은 로봇에 가 있었고, 태블릿은 그 사이사이에 잠깐 보는 화면이었습니다. 그렇다면 화면이 할 일은 스스로 눈길을 끄는 것보다, 로봇이 지금 왜 그렇게 움직이는지와 방금 차 안에서 나눈 이야기가 어떻게 이어지는지를 짧게 짚어 주는 것이었습니다. 다시 만든다면 화면을 로봇의 행동을 설명하고 기기 사이를 이어 주는 쪽으로 설계하겠습니다.

**세운 기준은 잴 방법까지 함께 정해야 했습니다.** 킥오프 때 "AI가 몇 명이었던 것 같나요?"라는 성공 기준을 세웠고, '같은 AI'라는 감각은 기술보다 연출의 문제라는 리스크도 미리 적어 두었습니다. 그런데 전시 현장에서 그 질문을 실제로 묻고 답을 모으지는 못했습니다. 그래서 이 프로젝트가 성공 기준을 채웠는지 지금도 제 인상으로밖에 말할 수 없습니다. 다음에는 기준을 세울 때 누가, 언제, 어떻게 물어서 기록할지도 함께 정해 두려고 합니다.
